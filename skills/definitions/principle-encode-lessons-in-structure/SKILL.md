An instruction stated twice as prose will be stated a third time. Encode it instead: a lint rule, metadata, a runtime check, or a script. Say it in structure so you never say it again.

Prose is read once and forgotten by Friday. The same review comment returns on the next change. The same mistake returns in the next file. The same warning returns in the next onboarding. Each return costs the full price of the first telling, paid by someone who never saw it. A codebase taught only in comments and chat is taught nowhere. The lesson exists wherever the last person who heard it happens to be looking.

**Turn the recurrence into structure.** If it can be checked, make it a lint rule or a runtime check. If it must travel with the code, make it metadata. If it is a pass over the tree, make it a script. Pick the form the machine enforces, because every form a human must remember is a form that decays.

**Do it at the second occurrence.** The first time is an anecdote. The second time is a pattern, and the pattern is the moment. Encode now, while the two examples are in front of you and the shape is exact.

This principle states no falsifiable test. There is no count to pass and no gate to clear. The signal is recurrence itself: the same lesson, needed twice, is the whole evidence, and the response is structure, not a stricter paragraph.

Reach for this the second time you write the same instruction or watch the same mistake return. Checking one claim once is principle-verification: run the command, make the claim, move on. Building the rerunnable tool for a batch of work is principle-build-the-lever, which owns the single pass while this one owns every pass after. Hand the lesson to the machine and stop paying the telling.
